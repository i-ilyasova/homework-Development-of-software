------- 3 ОСНОВНЫЕ ПРОБЛЕМЫ -------

Проблема 1: Медленная загрузка изображений (влияет на LCP)
  Описание: Изображения загружаются в формате JPEG/PNG без оптимизации.
            Отсутствует lazy loading. Главный баннер весит 1.2 МБ и
            загружается в оригинальном разрешении независимо от устройства.
  Решение:
    - Конвертировать изображения в формат WebP (сжатие на 25-35%)
    - Добавить атрибут loading="lazy" для всех изображений ниже fold
    - Использовать srcset и sizes для адаптивных изображений
    - Задать явные атрибуты width и height для предотвращения CLS
    - Настроить CDN с автоматической оптимизацией изображений

Проблема 2: Блокирующий JavaScript и CSS (влияет на FID и TBT)
  Описание: На странице подключены 14 сторонних скриптов (реклама,
            аналитика, виджеты) без атрибутов async/defer. Они блокируют
            парсинг HTML и задерживают интерактивность на 1.84 с.
  Решение:
    - Добавить defer для всех некритичных скриптов
    - Добавить async для независимых скриптов (аналитика)
    - Перенести сторонние скрипты в конец <body>
    - Использовать динамическую загрузку рекламных скриптов
    - Внедрить code splitting и tree shaking в сборке

Проблема 3: Нестабильность макета — CLS 0.38 (влияет на пользовательский опыт)
  Описание: Рекламные блоки и изображения вставляются в DOM без
            зарезервированного пространства. После загрузки шрифтов
            происходит сдвиг текста. Баннеры перемещают контент вниз.
  Решение:
    - Зарезервировать место для рекламных блоков через min-height
    - Добавить font-display: swap или optional для веб-шрифтов
    - Использовать aspect-ratio CSS для медиа-контейнеров
    - Задать фиксированные размеры для всех изображений в разметке

------- 5-6 ВТОРОСТЕПЕННЫХ ПРОБЛЕМ -------

1. Отсутствие preconnect для внешних ресурсов
   Решение: <link rel="preconnect" href="https://fonts.googleapis.com">

2. Неиспользуемый CSS (370 КБ из 620 КБ CSS не задействованы)
   Решение: Удалить мёртвый код, использовать PurgeCSS

3. Нет сжатия текстовых ресурсов (Brotli / Gzip не настроен)
   Решение: Включить сжатие на уровне сервера/CDN

4. Большой размер JavaScript-бандла (2.1 МБ не минифицированного JS)
   Решение: Минификация через Terser, разделение чанков, lazy-импорты

5. Шрифты загружаются без font-display
   Решение: @font-face { font-display: swap; }

6. Нет кэширования статических ресурсов (Cache-Control не задан)
   Решение: Настроить Cache-Control: max-age=31536000 для CSS/JS/изображений

------- ВРЕМЯ ПО ФАЗАМ -------

Loading (Загрузка ресурсов):   2 140 мс
  - HTML-документ: 180 мс
  - CSS-файлы: 620 мс (3 блокирующих файла)
  - Шрифты: 890 мс (Google Fonts без preconnect)
  - Изображения: 3 400 мс (продолжаются после записи)

Scripting (Выполнение JavaScript): 3 820 мс
  - Парсинг и компиляция JS: 760 мс
  - Выполнение основного бандла: 1 240 мс
  - Сторонние скрипты (реклама): 1 820 мс
  - Обработчики событий: 140 мс
  Проблема: Long Tasks > 50 мс обнаружены 7 раз (max 420 мс)
  Причина: тяжёлые рекламные фреймворки, выполняющиеся в главном потоке

Rendering (Рендеринг): 890 мс
  - Recalculate Style: 210 мс (избыточные правила, сложные селекторы)
  - Layout: 340 мс  ← ПРОБЛЕМА: 12 принудительных синхронных reflow
  - Paint: 180 мс
  - Composite: 160 мс

------- ОТВЕТЫ НА ВОПРОСЫ -------

Сколько времени занимает Loading:
  ~2.1 с для базовых ресурсов, 5+ с с учётом изображений и шрифтов.

Что происходит в фазах Scripting и Rendering:
  В Scripting основная нагрузка — сторонние рекламные скрипты, которые
  выполняются синхронно и блокируют главный поток на 3.8 с суммарно.
  Обнаружено 7 задач длительностью более 50 мс (Long Tasks), из них
  одна — 420 мс, что напрямую вызывает высокий FID.
  В Rendering фаза Layout занимает 340 мс из-за 12 принудительных
  синхронных reflow: JS читает offsetHeight сразу после изменения DOM,
  что вынуждает браузер пересчитывать компоновку синхронно.

Проблемы с Layout и Recalculate Style:
  Да. Recalculate Style занимает 210 мс из-за специфичных CSS-селекторов
  с глубокой вложенностью. Layout — 340 мс из-за reflow, вызванного
  вставкой рекламных блоков без зарезервированного пространства.


===========================================================================
ЗАДАНИЕ 3. ОПТИМИЗАЦИЯ РЕНДЕРИНГА (150-200 слов)
===========================================================================

Главный приоритет оптимизации критического пути рендеринга — устранение
блокирующих ресурсов. Необходимо перенести все сторонние JavaScript-скрипты
(аналитику, рекламу) в конец документа с атрибутами defer или async, а
некритичный CSS загружать через media="print" с переключением на all после
загрузки. Критические стили (above-the-fold) следует встроить напрямую в
<head>, чтобы браузер отрисовал первый экран без ожидания внешних файлов.

Для сокращения Loading необходимо добавить <link rel="preconnect"> и
<link rel="dns-prefetch"> для всех сторонних доменов, а изображения
конвертировать в WebP с адаптивным srcset. Шрифты Google Fonts следует
заменить на самостоятельно хостируемые с font-display: swap, что исключит
блокировку текста при загрузке.

Для устранения Layout Thrashing необходимо батчинг DOM-операций через
requestAnimationFrame и разделение операций чтения/записи геометрических
свойств. Рекламным блокам нужно задать фиксированные min-height через CSS
aspect-ratio до загрузки контента, что снизит CLS с 0.38 до целевых < 0.1.
Эти изменения должны поднять Lighthouse Performance с 42 до 80+ баллов.

ЗАДАНИЕ 4. РЕАЛИЗАЦИЯ ОПТИМИЗАЦИИ
===========================================================================

Реализована демонстрация оптимизации на собственной HTML-странице.
Файлы: before.html (до оптимизации) и after.html (после оптимизации)

Сравнение результатов Lighthouse:
  До  (before.html): Performance ~35, LCP ~8.2 с, CLS ~0.45, TBT ~2100 мс
  После (after.html): Performance ~94, LCP ~1.8 с, CLS ~0.02, TBT ~60 мс

Применённые оптимизации в after.html:
  1. Критический CSS встроен inline в <head>
  2. Внешние стили загружаются асинхронно
  3. Все скрипты имеют атрибут defer
  4. Изображения: loading="lazy", srcset, явные width/height
  5. <picture> с WebP + JPEG fallback
  6. preconnect для внешних ресурсов
  7. font-display: swap для шрифтов
  8. Зарезервированные размеры для рекламных блоков (aspect-ratio)
  9. will-change: transform для анимированных элементов
  10. Минифицированный CSS без неиспользуемых правил
